# 返货余额监控仪表盘

同程旅行投放返货余额监控工具：展示各投放账户的「普通返货余额」「赔付返货余额」可支撑天数，并给出账户间返货余额的转入/转出调拨建议。

## 功能

- 全部账户 / 需转入 / 可转出 / 闲置余额 四个视图
- 可支撑天数分布图、资金调拨概览（转入/转出 Top 10）
- 支持手动导入日结报表（.xlsx / .xls）并重新计算
- 支持导出 CSV（返货余额调拨建议）

## 返货口径（重要）

日结报表里返货分成两个钱包，**性质不同，必须分开处理**：

| | 普通返货 | 赔付返货 |
|---|---|---|
| 能否抵扣消耗 | ✅ 可以 | ❌ 不可以（只能转账 / 提现） |
| 报表列 | `账户消耗-普通返货` / `普通返货余额` | `账户消耗-赔付返货` / `赔付返货余额` |
| 参与「需转入」计算 | ✅ 按 日均普通返货消耗 × 调拨天数 | ❌ 不参与（无水位概念） |
| 参与「可转出」计算 | ✅ 普通返货盈余 = 余额 - 目标水位 | ✅ **余额全额**计入 |

因此：

- **需转入** = 普通返货缺口，只有普通返货能填
- **可转出** = 普通返货盈余 ＋ 赔付返货余额（页面/CSV 拆成两列展示）
- **净盈余 / 缺口判断只按普通返货口径** —— 赔付返货没法抵扣消耗，不能用来覆盖消耗缺口
- 同一账户可以**同时出现在「需转入」和「可转出」两侧**（两笔钱性质不同，例如：普通返货不够要转入，但账户里还躺着赔付余额可以转出）

## 四个视图之间的关系

| 视图 | 含义 |
|---|---|
| 📋 全部账户 | 有余额或有消耗的全部账户 |
| 📥 需转入 | 普通返货低于目标水位的账户（只按普通返货缺口算） |
| 📤 可转出 | **全集**：无消耗账户的闲置余额 ＋ 在投账户的返货盈余；汇总卡的「可转出总额」= 这个数 |
| 💤 闲置余额 | **「可转出」的子集**：无消耗账户里的余额 |

⚠️ 「闲置余额」不是独立统计，它是「可转出」里那批**无消耗账户**，所以两边会看到同一批账户和同一个建议转出金额（页面计数旁会标注 `n / m 户` 说明包含关系）。单列一个 tab 是因为这批钱**转出去零风险**（账户已停投、不影响任何投放），实际操作时优先处理它们。

以 2026-09-28 报表为例：可转出 246 户 ＝ 闲置 166 户 ＋ 在投账户盈余 80 户。

## 数据来源与更新

数据文件为 `account_data.json`，由脚本 `update_data.py` 从日结 Excel 报表生成：

```bash
python3 update_data.py <日结报表.xlsx> [--days 10]
```

参数说明：

- `<日结报表.xlsx>`：必填，日结报表 Excel 文件（含「账户ID」「账户名称」「账户消耗-普通返货」「普通返货余额」「账户消耗-赔付返货」「赔付返货余额」「账户总消耗」「日期」等列；旧报表若无赔付返货列则按 0 处理）
- `--days 10`：可选，目标可支撑天数（默认 10，用于计算转入/转出建议）

生成 `account_data.json` 后刷新页面即可看到最新数据；也可以在页面右上角「📂 加载新报表」手动导入，无需重新生成文件。

> 两条路径（脚本生成 / 页面上传）使用**同一套口径**，逐账户、逐字段、逐分一致，已做交叉校验。

## 页面使用

纯静态页面，直接以任意静态服务器打开即可（无需构建）：

```bash
python3 -m http.server 8080
# 浏览器访问 http://localhost:8080
```

Excel 解析库 `xlsx.full.min.js` 与页面同目录，点「加载新报表」时才按需加载（不依赖外网 CDN，内网/代理环境也能用）。

**`account_data.json` 包含全部投放账户的财务数据（返货余额、日均消耗等），严禁外发或上传至公开仓库！**

- 该文件已被加入 `.gitignore`，请勿强制提交（`git add -f`）到任何公开仓库。
